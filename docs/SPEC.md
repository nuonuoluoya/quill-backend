## 1. 原规格分析与迁移结论

### 1.1 可延续的产品核心

现有项目是本地优先的逐句英语听力工具：读取独立音频项目输出的书籍包，提供章节浏览、原文阅读、逐句播放、循环、章内连续播放、倍速、本章搜索及句子级进度。

以下约束继续成立：

- 音频处理与学习应用分离；应用不进行 ASR、对齐、修边或人工审核。
- 句子身份与内容版本明确；不可播放句子保留原文和原因。
- 单一播放通道，切句无叠音，过期请求不能恢复旧音频。
- 逐句模式下循环与连播互斥；逐句连播遇到不可播放句、错误或章末停止。新增的全文播放使用独立整章音频，规则见第 7.5 节。
- 首次进入、恢复位置、切章和应用内容更新均不自动发声。
- 应用功能验收与上游音频内容质量验收分开。

### 1.2 必须改变的设计

| 原网页规格 | 小程序版决定 | 影响 |
|---|---|---|
| 本地静态 JSON / MP3，无业务后端 | API 提供内容与进度，私有媒体服务提供 MP3 | 新增后端、数据库、鉴权和部署 |
| Vue + 浏览器 DOM | uni-app Vue 3 编译为微信小程序 | 复用纯逻辑，重做页面和平台适配 |
| `HTMLAudioElement` | 微信 `InnerAudioContext` 播放适配器 | 重写播放器驱动和生命周期处理 |
| 浏览器 `localStorage` | 小程序本地进度缓存 + 服务端进度 | 新增账号隔离、重试、冲突处理 |
| JSON 文件经 U 盘迁移进度 | 同一微信身份跨设备同步 | 文件导入导出退出 MVP |
| 手工替换 `books/current/` | 运维导入、校验、发布不可变内容版本 | 客户端固定到一个 `buildId` |
| Windows U 盘离线启动 | 微信内在线使用 | 不承诺全书离线、U 盘使用或电脑便携运行 |
| 桌面侧栏、键盘快捷键 | 手机章节页、阅读页、底部播放器 | 手势和触屏为主 |
| 书籍仅存在用户本地 | 内容存储在服务端并受授权控制 | 需要独立确认服务端存储及分发范围 |

## 2. 产品目标、范围与默认决策

### 2.1 产品目标

用户在微信内打开 Pidan Vocal，从书架选择小说，再选择章节，阅读英文并逐句听音频，或点击“全文播放”从头到尾一次播完当前章节；退出后保留每本书的句子级阅读位置，登录后可在同一微信身份的其他设备恢复阅读位置和速度。

首版提供轻量书架，支持从一本书平滑扩展到多本小说；实际上线可以只提供一本。导航为“书架 → 书籍章节目录 → 阅读页”，书籍和章节由内容接口返回，不在客户端硬编码。新增小说通过导入、发布和授权完成，无需为每本小说开发新页面或重新发布小程序。

书架分为“我的书籍”和“体验样本”：前者列出当前账号已获授权且有活动构建的私有书籍，后者列出已发布的公开样本，对应第 9.2 节的 audience。游客可直接使用体验样本，并可主动登录查看自己的书籍；登录失败不自动改换已打开的书籍。样本必须使用独立于私有全书的 bookId，不能通过把同一书籍改为公开而意外开放其历史私有构建。移除单书 `sampleBookId/memberBookId` 入口配置要求；没有可见书籍是正常空状态，不能冒充服务故障。

本文中的“当前书籍”指用户当前选中的 bookId；每本书各自拥有 activeBuildId。最近打开的书籍只用于提供继续学习入口，不是所有用户共用的环境级当前书籍。

### 2.2 MVP 必需功能

1. 书架入口、多书选择、每本书的章节目录、样本/完整包标记和可播放数量。
2. 章节内英文句子列表、当前句高亮、播放/暂停、上一句/下一句。
3. 本句循环、章内连续播放及 `0.75× / 1× / 1.25× / 1.5×` 倍速。
4. 当前章纯文本搜索；搜索不改变原始播放顺序。
5. 本地句子级进度保存、微信登录后的云端同步、跨设备冲突提示。
6. 内容、网络、登录、权限、播放与存储错误的明确状态和重试入口。
7. 后端接收 v2 数据包、校验、发布、回退；通过运维 CLI 完成，无需开发管理网站。
8. 私有内容授权、短时效媒体访问、日志脱敏、基础监控和恢复文档。
9. 当前章节全文播放：使用一条完整章节音频从头播至章末，支持暂停/继续和四档倍速，与逐句播放共用同一个播放器；不自动跨章。

### 2.3 首版不包含

- 小程序内导入原书、上传 ZIP、录音、语音评分、ASR、对齐或剪音频。
- 翻译、词典、背词、听写、AI 对话、全书搜索、社交、支付和会员体系。
- 书城推荐、分类榜单、购书、收藏/手动增删书架、书架搜索与自定义排序；逐句学习评分、学习排行榜或将播放次数当作学习完成度。
- 后台/锁屏持续播放、系统媒体控制、订阅消息、自动跨章连播。
- 整本音频下载、永久离线缓存、文件系统浏览、U 盘进度文件导入导出。
- 将现有 HTML 放在 `web-view` 中作为正式小程序交付。
- H5、App、桌面微信、平板专属布局的完整兼容承诺。

### 2.4 已作出的产品默认值

- 采用前台听力模式：离开阅读页、应用进入后台或发生系统音频中断时暂停，返回后由用户手动继续。
- 合规样本允许游客试用，只保存本机进度；真实私有书籍需要登录及书籍访问授权。
- 微信登录用于确定账号身份，不要求手机号、头像、昵称、通讯录或定位。
- 云同步替代旧版 U 盘迁移，不自动导入现有网页的浏览器存储；老版进度迁移可另立后续需求。
- 客户端不是管理员，不拥有上传内容、发布版本或修改审核状态的权限。

AppID、部署域名、运营主体、内容授权范围、目标手机和基础库版本在上线前落实。这些部署参数不阻塞样本、契约和应用开发，但缺失时不能宣布已具备正式发布条件。

## 3. 总体架构与前后端边界

```text
独立音频处理项目
    │ 交付 book-package v2（JSON + 独立 MP3）
    ▼
后端运维 CLI ── 校验/导入 ──► PostgreSQL（内容索引、账号、权限、进度）
    │                       │
    └── 不可变资源上传 ──► 私有对象存储
                            │
微信小程序 ── HTTPS JSON ──► 独立 API 后端
    │                       │ 登录服务端换取微信身份
    └── 短时效 HTTPS 音频 URL ──► 鉴权媒体域名/CDN ──► 私有对象存储
```

### 3.1 职责划分

| 层 | 承担职责 | 不承担职责 |
|---|---|---|
| 音频处理项目 | 提取、分句、对齐、裁剪、补白、质量审核，输出包含逐句素材及整章音频扩展的 v2 包 | 账号、学习进度、小程序 UI |
| 小程序前端 | 页面、交互、搜索、音频控制、本地进度、API 调用 | 决定内容权限、签发 URL、直接连接数据库 |
| API 后端 | 登录会话、访问授权、内容查询、媒体授权、进度校验与同步 | GPU 运算、实时转码、生成逐句音频 |
| 数据库 | 账号、会话、内容版本/索引、授权、进度、幂等记录 | 储存 MP3 二进制 |
| 对象存储/媒体网关 | 私有音频、不可变路径、有效签名校验、Range 读取 | 决定用户当前位置或更改句子文本 |
| 运维 CLI | 完整包校验、导入、发布、授权用户、回退 | 对普通小程序用户开放管理权限 |

### 3.2 分离的验收标准

- 前端仅使用公开的版本化 HTTP 契约和媒体 URL；不导入后端实现，不共享数据库凭据。
- 后端独立启动；可用 HTTP 测试客户端完成登录模拟、内容查询、进度读写及权限测试。
- 前端可使用契约驱动的 Mock API 独立开发；正式构建中不得开启 Mock 登录或 Mock 播放成功。
- 内容更新或后端兼容性升级不要求重新发布小程序；小程序更新不要求迁移或重新切割音频。
- 共享目录只放 Schema、DTO、OpenAPI 与纯业务规则；禁止将 NestJS、ORM、Node 文件系统模块打进小程序。
- 首版采用独立服务端部署，不让小程序直连云数据库；是否使用同一云厂商托管不影响前后端边界。

### 3.3 技术与环境

- 前端：uni-app、Vue 3 Composition API、TypeScript；平台能力集中在 `platform/wechat/`，通过微信接口操作音频、登录、网络和存储。
- 后端：NestJS 模块化服务、REST/JSON、OpenAPI 3.0、PostgreSQL；媒体存储使用可配置适配器，首个部署可接腾讯云 COS。
- 首版不要求 Redis、消息队列或微服务；内容 CLI 执行离线导入，API 不执行长时间处理任务。
- 版本在实施阶段验证并锁入各自 lockfile；不直接沿用现有网页的 Vite 版本作为 uni-app 兼容保证。
- `development / staging / production` 配置隔离，数据库和存储前缀隔离；客户端只包含 AppID、环境标记和公开 API 基址。

## 4. 输入数据包兼容规范

### 4.1 目录与版本

```text
book-package/
  book.json
  chapters/c01.json
  chapters/c02.json
  audio/c01/c01-s0001.mp3
  audio/c01/c01-s0002.mp3
```

继续使用现有 `schemas/book-v2.schema.json` 和 `schemas/chapter-v2.schema.json` 作为输入格式，结合业务校验执行；API 自身版本为 `/v1`，二者不是同一个版本号。原网页 `progressSchemaVersion: 1` 是文件迁移格式，不直接用作云端并发写入协议。

- `schemaVersion` 必须为 `2`；未知版本拒绝导入，不静默按旧版解释。
- `buildId` 标识不可变完整包；任何音频、路径、审核状态或内容改变都生成新值。
- `textRevision` 标识正文和分句身份。仅修正音频可保持该值；改变文本、分句或句子身份必须更新。
- 全书及每章的 `bookId / buildId / textRevision` 一致，顶层书籍 ID 为 `book.id`。
- `contentScope` 为 `sample` 或 `complete`，保留原意并在页面展示。
- 章节 `data` 和句子 `audio` 都相对包内 `book.json` 所在目录解析。
- 包内路径使用 `/`，拒绝绝对路径、盘符、外部 URL、反斜线、查询参数、片段、控制字符、编码后越界路径和越界符号链接。
- 输入包不能指定任意云端下载源；后端不根据包字段请求互联网地址。

### 4.3 必须保持的业务约束

- 章节顺序以清单数组为准；章节 ID 唯一，句子 ID 在同一书籍构建内全局唯一，章内 `index` 从 1 连续递增。
- `sentenceCount` 包括不可播放句；`playableCount` 必须等于实际可播放条目数。
- 章节 `duration` 是源章节时长，不是片段时长总和；与 `chapterDuration` 的差值不超过 `0.10s`。
- `auto_passed`、`verified` 可播放，要求非空 MP3 路径及正的有限 `duration`。
- `needs_review`、`unmatched`、`excluded` 不可播放，要求 `audio = null`、`duration = null` 且至少一条原因。
- 未知审核状态、状态与音频字段冲突、重复 ID、错误计数都拒绝导入。
- `timing` 可选，若存在须完整：`0 <= clipStart <= speechStart < speechEnd <= clipEnd <= chapterDuration`；两侧缓冲等于对应边界差、均为 `0～0.5s`，片段长度与 `duration` 误差不超过 `0.10s`。
- `sourceTiming` 与 `padding` 必须成对出现，并与 `timing` 互斥；源范围不越章，每侧数字静音 `0.2～0.5s`，成品时长约等于源长度加两侧静音，允许 `0.10s` 编码误差。
- `sourceText` 可保留经录音依据修订前的原文；不通过 ASR 猜测静默重写文本。
- 文本和原因按纯文本展示。独立 MP3 从自身 `0` 开始播放，不把源章节时间戳作为片段播放位置。

### 4.4 内容质量与导入检查

导入遍历全部章节及可播放文件，检查 Schema、跨章身份、路径、全书 ID、非空文件、实际 MP3 格式和解析时长。元数据检查不承担音频重切或模型推理。解析时长与声明时长误差不超过 `0.10s`；解码损坏仍通过真实播放抽查和运行时错误处理发现。

原规格的对齐覆盖率 `>= 99%`、抽样至少 `95%` 同时满足内容正确/首尾完整/不含邻句语音，继续作为上游目标。当前可播放比例约 `96.97%`，不能宣称已达到该覆盖目标。格式有效的部分可播放包允许受控联调，必须如实显示数量；全书内容合格与小程序功能合格分别出具结论。

### 4.5 整章音频扩展（全文播放）

全文播放使用上游交付的完整当前章节 MP3，不拼接逐句 MP3，也不以逐句连播代替。这样不会引入每句补白产生的间隔，也不会因某句尚未可靠对齐而中断整章聆听。上游负责确认整章录音的章节归属、完整性及可使用范围，后端不在线合成或重新处理音频。

在章节 JSON 顶层增加可选扩展 `chapterAudio`，继续使用 `schemaVersion: 2`；路径相对包内 `book.json`。建议文件位置为 `audio/chapters/c01.mp3`：

```json
{
  "chapterAudio": {
    "status": "available",
    "audio": "audio/chapters/c01.mp3",
    "duration": 60,
    "reasons": []
  }
}
```

上例只展示新增字段，不是可单独导入的完整章节。扩展规则：

- `status` 仅允许 `available / unavailable`；available 要求包内完整 MP3 路径、正的有限 duration，且 reasons 为空；unavailable 要求 audio/duration 为 null，并至少给出一条原因。
- 整章 MP3 从源章节起点到终点完整保留，声明及解析时长与 `chapterDuration` 的误差均不超过 `0.10s`；不能用单句片段或不完整拼接文件冒充全文。
- 导入校验扩展的字段、路径安全、文件格式、哈希、时长和归属；业务/API 契约同步补充该扩展，不能依靠旧 Schema 允许未知字段就跳过检查。
- M0 必须为 `chapterAudio` 增加显式 Schema 和业务校验及正常/异常样本；缺失字段兼容旧包，存在但结构非法（包括 null）必须拒绝。现有 `schemas/chapter-v2.schema.json` 尚未定义该扩展，当前旧校验器通过不代表扩展有效。
- 缺少该扩展的旧 v2 包仍可导入，整章能力标为 unavailable，原逐句功能保持可用；页面显示“本章全文音频暂不可用”。不得宣称旧包已满足全文播放验收。
- 新增、更换或修复整章音频必须生成新 buildId；正文不变可保留 textRevision，资源发布与回退仍跟随整个构建。
- `chapterAudio.status` 与句子 `alignment.status` 独立：完整章录音可用不代表每句已对齐；句子待复核不自动禁止已独立验证的完整章音频。章节音频本身缺失/不可用或内容撤销时禁止全文播放。
- 正式声明某本书支持全文播放前，其全部有内容章节必须提供 available 的完整章音频；兼容旧包或单章样本通过不等于全书能力完成。

## 5. 内容导入、发布与版本一致性

### 5.1 运维流程

1. 管理员在受控后端环境放入已解压的数据包，运行独立 `validate-book`；记录清单摘要、文件数量和校验结果。
2. 导入创建 `staged` 构建；把对象上传到 `books/{bookId}/{buildId}/...`，服务器生成对象键，不直接把不可信 ID 当作磁盘路径。
3. 入库章节/句子索引、审核状态和整章音频可用状态；核对逐句及整章对象存在、大小、SHA-256、时长和内容计数，成功后转为 `ready`。
4. 管理员声明内容使用范围，选择 `sample-public` 或 `private`，并与书籍创建时确定的可见性一致。只有原创/明确获公开授权内容可设为公开样本；MVP 不支持原地将私有书籍及其历史构建改成公开样本。
5. 发布在数据库事务中切换书籍的 `activeBuildId`；新用户只读新指针，禁止逐文件覆盖已发布构建。
6. 发布后通过真实 API 和音频 URL 验证；异常时把活动指针切回仍可用的旧构建。

相同 `(bookId, buildId)` 与相同校验摘要重复导入为幂等操作；摘要不同则拒绝。失败导入不影响在线版本。孤立上传对象可由后续清理任务处理，不在失败时误删线上资源。

新构建复用同一 `textRevision` 时，导入器必须比对已有正文的章节/句子身份、顺序和文本；发现变化则拒绝并要求上游生成新正文版本。只检查字符串相等不能证明进度可兼容。允许审核状态、音频引用及音频诊断信息在正文不变时更新。

包摘要采用确定性算法：对 book.json、全部引用的章节 JSON、逐句及整章 MP3，按规范化相对路径排序，记录每个文件的路径、字节数与 SHA-256，再对清单计算 SHA-256；不包含文件修改时间、机器绝对路径或未引用文件。导入仅上传清单内文件，校验到上传期间须固定输入快照并复核哈希，避免“校验的是 A、上传的是 B”。时长和哈希不能证明语义上的章节归属；完整性与归属仍须记录上游审核及抽听结论。

### 5.2 客户端固定内容快照

- 进入阅读时取得 `bookId + buildId + textRevision`，章节与媒体请求显式带此快照身份。
- 发现新构建只显示“内容有更新”；用户确认或下次重新进入后停止旧播放、取消请求、清空旧章缓存，再读取新清单。
- 普通发布后旧构建从被替换时起默认保持可读至少 7 天，方便正在学习的会话结束；到达保留截止时间后返回 `410 BUILD_RETIRED`，提示加载新版本，不暗中混用新章节。
- 内容紧急下架可立即把构建设为 `revoked`；API 立即拒绝新访问和签名。已签发 URL 的残余有效期见第 8 节。
- 回退只能指向 `ready` 或仍可读的历史完整构建；不得恢复已经撤销的内容。
- 只变 `buildId`、`textRevision` 不变时按句子 ID 验证并保留进度；正文版本变化不按旧序号猜测位置。

### 5.3 构建状态与清理

| 状态 | 普通内容/媒体 API | 发布与迁移规则 |
|---|---|---|
| `staged` | 不可读，返回 404 | 上传或校验未完成；失败保持隔离 |
| `ready` | 不可读，返回 404 | 完整校验通过、尚未发布；可原子发布为 active |
| `active` | 授权后可读 | 每本书至多一个，必须与 activeBuildId 一致 |
| `retained` | 保留截止时间前授权可读 | 已被替换；保留期内可回退为 active |
| `retired` | 返回 410 BUILD_RETIRED | 不可直接回退；如需恢复，先经运维重新核对全部对象并恢复为 ready |
| `revoked` | 返回 410 BUILD_REVOKED | 紧急撤销；该 buildId 不得重新发布 |

发布/回退在同一事务中将目标设为 active、原活动构建设为 retained 并设置其新保留截止时间。并发操作需比较管理员读取的预期 activeBuildId，过期操作失败，避免相互覆盖；回退到当前活动构建为幂等无操作。撤销活动构建同时清空活动指针，不能自动回退到未经选择的内容。

retained 的新签名有效期不得超过其可读截止时间；授权接口保守按完整资源时长 / 0.75 加 30 秒判断，剩余保留期不足则返回 `409 BUILD_UPDATE_REQUIRED`，提示用户选择更新，不签发必然中途过期的 URL。该限制不追溯缩短之前已签发的 URL，其残余有效期仍见第 8.3 节。清理对象须晚于可读截止时间和最后已签发 URL 到期时间，且不得影响 active 构建或历史进度身份索引。

### 6.2 阅读页布局

```text
┌────────────────────────────┐
│ 返回  Chapter 1     章节选择 │
│ 本章搜索…          清除     │
│ 全文播放（当前章节）        │
│ 样本内容 / 待同步提示       │
├────────────────────────────┤
│ ▶ 001  English sentence…   │
│ ❚❚002  Current sentence…   │
│ — 003  English sentence…   │
│        待复核：原因…         │
│ …                          │
├────────────────────────────┤
│ 当前句 002 / 342   定位原文  │
│ 上一句    播放/暂停   下一句  │
│ 1×       本句循环   章内连播 │
│        底部安全区           │
└────────────────────────────┘
```

- 适配胶囊区、状态栏和底部安全区；底部播放器不遮挡最后一行，键盘弹起时搜索和清除按钮可操作。
- 句子序号、原文、播放状态始终可辨；播放状态同时使用文字/图标，不只靠颜色。
- 主要触控目标至少约 `44 × 44` 逻辑像素；英文支持换行，字号和行距适合长时间阅读。
- 状态区分默认、选中、加载中、播放中、暂停、结束、失败、不可播放；失败有句子标识和重试。
- 用户切句时定位该句；用户主动滚动阅读后，连播不持续抢滚动位置，显示“定位当前句”。
- 逐句模式下搜索过滤隐藏当前句时，底部仍显示当前句摘要并可操作；“定位原文”先清除查询再滚动。
- 阅读页提供清晰的“全文播放”入口；进入整章模式后底部显示“全文播放 · 当前章标题”、已播/总时长、暂停/继续、从头播放及倍速。逐句导航、循环和连播控件收起，提供“返回逐句”操作。
- 空书籍/空章节、无搜索结果、无权限和数据加载失败使用独立空状态，不显示假的播放按钮。
- 采用平台可用的无障碍标签，实测系统读屏；不把浏览器键盘快捷键和 CSS 媒体查询当作小程序能力。

### 6.3 搜索

完整加载当前章节后在本机按纯文本连续子串匹配，忽略大小写、去除首尾空白；不使用正则解释用户输入，不渲染输入生成的 HTML。空查询恢复全章，结果按原文顺序；切章清空查询。搜索不切句、不停止音频，上一句/下一句和连播始终基于原文顺序。

全文播放不受搜索结果影响，仍播放完整当前章；全文模式下不显示逐句上一句/下一句按钮，点击某个句子的播放按钮才切回逐句模式。

### 6.4 书架入口与多书导航

设计任务是让用户找到并切换将来新增的小说，同时保留每本书的学习位置。书架承载选书，现有目录和阅读页继续承载选章与播放；书架不承担购买、上传或内容管理。对应 `rule/smallest-intervention`、`rule/navigation-vs-action`。

- 普通冷启动进入书架，即使只有一本书也保留入口；明确的书籍/章节深链接除外。已登录默认展示“我的书籍”，游客默认展示“体验样本”，两个入口可见且可切换；不强制弹登录框。使用小程序导航组件表达选书与返回，读屏可识别书名和导航目标。对应 `rule/control-matches-cardinality`、`rule/value-before-interruption`、`rule/accessible-name-required`。
- 书籍条目展示书名、语言/版本、章节数和样本/完整包标记；纯文字封面即可完成首版，不将真实封面素材作为上线前置条件。全文能力显示“全部章节可用 / 部分章节可用 / 暂不可用”，按整章资源计数推导，不能把逐句可播放比例当作全文能力。点击条目进入该书目录，不直接发声。对应 `rule/smallest-intervention`、`rule/navigation-vs-action`。
- 有本机最近阅读记录时提供一个“继续学习”主入口，标明书名与位置；进入时重新获取该书活动构建、校验权限，并按第 10 节恢复/解决云进度冲突，不自动播放。记录过期、正文变化或权限失效时说明原因并提供目录/书架入口；不要自动替换成另一本书。最近书籍不在列表首批中时，可单独查询它，不加载所有页寻找。对应 `rule/one-primary-action`、`rule/preserve-mental-model`。
- 返回书架或换书时，先保存当前书的本地位置，停止音频、取消该书播放意图并清除整章临时秒数、章内搜索和循环/连播状态。原书待同步记录按自己的进度键继续保留；其后台同步响应不能改变新书界面。新书恢复自己的位置与速度偏好，不能沿用上一书的 chapterId/sentenceId。换书是可返回的导航，无需确认弹窗；同步失败显示状态，不阻止换书。对应 `rule/preserve-mental-model`、`rule/preserve-user-input`、`rule/inline-before-modal`。
- 从目录返回书架保留当前分类、已加载列表与滚动位置，提供显式刷新及加载更多控件，不依赖手势才能完成导航。重新登录/退出后清理旧身份的私有列表及最近书籍标记。对应 `rule/preserve-mental-model`、`rule/gesture-has-control-alternative`。

书架必须覆盖以下状态（`rule/cover-reachable-states`、`rule/empty-state-action`、`rule/error-states-recovery`）：

| 状态 | 行为及恢复路径 |
|---|---|
| 首次加载/只有一本/多本 | 有明确加载反馈；一本不自动跳转，多本按接口顺序列出 |
| 游客查看我的书籍 | 说明需登录，保留体验样本入口，不暴露私有书名 |
| 已登录但无已授权书籍 | 显示无可访问书籍，提供体验样本、刷新及联系运营的入口，不伪装成加载失败 |
| 公开样本为空 | 显示暂无样本，允许刷新或登录查看已授权书籍 |
| 首次加载失败/断网 | 说明无法取得书架并可重试；已有同身份内存列表可显示为待刷新，不假报最新 |
| 加载更多失败 | 保留已加载条目及滚动位置，只重试失败页，不把现有列表清空 |
| 列表显示后撤权/下架/更新 | 进入书籍时再次校验；拒绝访问则说明原因并刷新列表，更新按快照规则处理 |
| 长书名/无封面/读屏 | 书名可完整读取，文本封面不影响进入；控制名称包含对应书名，触控与读屏均能完成选书和返回 |

## 7. 播放器规格与微信生命周期

### 7.1 平台适配和状态机

全应用一个播放器服务，同一时刻最多一个有效 `InnerAudioContext`，逐句与全文模式共用该服务。界面组件仅发出播放命令，不创建自己的音频对象。底层使用 `wx.createInnerAudioContext()`；保持 `autoplay = false`，UI 状态以实际音频事件为准。

微信官方类型声明包含 `playbackRate`（基础库 2.11.0 起，范围 0.5～2.0）及音频中断事件。这为四档倍速和中断处理提供接口依据，不能替代真机测试。[接口依据](https://raw.githubusercontent.com/wechat-miniprogram/api-typings/master/types/wx/lib.wx.api.d.ts)

```text
idle → selected → loading → playing ⇄ paused
                       └→ error       └→ ended
不可播放句 → unavailable
换句/换章/退出/内容撤销 → 取消旧意图并进入对应状态
```

- 每次选句/换源创建新的 `operationId`；异步媒体授权、章节请求、重试和播放回调绑定该操作身份。
- 播放目标显式记录 `mode: sentence | chapter` 及 bookId/buildId/chapterId；sentence 模式另带 sentenceId。切换模式等同换源，不能让逐句 ended 回调推进正在播放的整章音频，反之亦然。
- 微信音频事件不保证携带业务句子 ID，不能只在回调中读取“当前句”就当作事件来源。换源采用停止、解绑旧监听并销毁旧实例，再创建并绑定新实例的顺序；任一时刻只保留一个有效实例。
- 暂停/继续同一句可复用实例；再次加载、换 URL 或切句均增加操作序号，旧实例回调直接丢弃。
- 音频实例身份与“允许开始播放”的意图分开保存。暂停、取消加载或退后台立即撤销播放意图、后续重试和自动切句；即使实例保留，也不能仅凭 operationId 相同就在迟到的授权/canplay/seeked 回调中调用 play。继续必须创建新的用户播放意图，并确认仍在前台阅读页、身份及快照未变化。
- `playing` 必须由当前操作的实际播放事件确认；`onCanplay` 不等于已经播放。停止、错误、超时和中断同步更新 UI。
- 模式由状态机处理自然结束事件，避免原生 loop 与连播逻辑同时驱动。每次生命周期取消后旧结束事件不得启动下一句。

### 7.2 操作规则

本节表格描述逐句模式；全文模式以第 7.5 节为准。

| 操作/事件 | 必须行为 |
|---|---|
| 点击可播放句 | 立即选中，取得当前快照的媒体授权，加载并尝试播放 |
| 再次点击当前播放句 | 暂停；再次点击从暂停点继续 |
| 当前句已结束后点击 | 从独立片段的 0 开始 |
| 加载中再次点击 | 取消待播放意图，停留在选中状态；迟到响应不得自动播放 |
| 点击其他句 | 停止旧音频、作废旧请求、切换并加载新句 |
| 上一句/下一句 | 按原文顺序；此前正在播放/等待播放则尝试播放新句，否则只选中 |
| 导航遇到不可播放句 | 停止并显示原因；不跳过、不签发该句媒体 URL |
| 章首/章末 | 禁用超界按钮；连播在章末结束，不自动跨章 |
| 手动切章 | 停止旧音频，取消请求，关闭循环/连播，默认选新章第一句，不自动播放 |
| 开启循环/连播 | 两者互斥；只改变模式，不因开关本身启动静止的播放器 |
| 当前句自然结束 | 循环则重播本句；连播则按原文进入下一句；否则保持 ended |
| 点击不可播放提示 | 可选中并查看原因，播放动作禁用 |

循环播放完整片段；逐句连续播放串接完整片段，保留上游已生成的静音，不承诺无缝播放。全文模式直接播放完整章节文件。首版两种模式均不提供拖动进度条；暂停点仅在当前阅读会话有效，持久进度只保存句子位置。

### 7.3 倍速和错误

- 四档速度在换句后保持；为新实例设置速度，不能只更新界面数字。
- 以能力检查、基础库配置及目标机型实测决定是否允许倍速；不支持时明确禁用非 1× 并提示升级。降级设备不算四档倍速验收通过。
- `preferredSpeed` 是用户偏好，`effectiveSpeed` 是当前设备实际应用档位；降级到 1× 不自动覆盖云端偏好。
- 遵循系统静音策略；无声时提示检查媒体音量、静音/蓝牙输出，不全局强制抢占其他音频。
- 从媒体授权完成开始，默认 15 秒未能确认播放则显示超时并取消该播放意图；请求/播放器迟到事件不得假报成功。
- 播放中持续 15 秒没有播放时间推进（暂停、中断和已结束除外）进入缓冲超时，按第 8.3 节有界恢复；加载、定位、重试各阶段都必须能取消。一次用户播放意图共用一份重试预算，网络层、登录层与播放器不得嵌套倍增重试；总等待默认不超过 60 秒，到期保留位置并提供手动重试。
- 文件不存在、解码失败或时长明显异常时，逐句模式保留选中句并停止循环/连播；全文模式保留当前章及最后确认播放时间并停止播放。两者均提供手动重试，不改变上游审核状态。
- 输入包严格时长检查在后端导入完成；客户端元数据非零且稳定后可做异常诊断，不能把平台尚未就绪时的 `duration = 0` 当成坏音频。

### 7.4 前后台与退出

- 阅读页 `onHide/onUnload`、应用 `onHide` 或系统音频中断开始时：暂停，作废所有待播放、定位后播放、重试和自动续播意图，保存本地位置，尽力同步但不依赖离开事件完成网络请求。重复生命周期通知按幂等处理。
- 回到前台/阅读页或中断结束：恢复 UI，不自动发声；循环与连播关闭，用户重新操作后才继续。
- 应用销毁或阅读页卸载时销毁音频实例；冷启动恢复句子，不恢复句内秒数。
- 章节选择抽屉和倍速菜单作为阅读页内交互，不因打开菜单中断音频。
- 不使用 `BackgroundAudioManager`，不配置后台音频作为 MVP 能力；锁屏播放属于后续独立需求。

### 7.5 全文播放：一次播完当前章节

- “全文”在本产品中指当前章节，不是全书。用户点击“全文播放”后立即停止逐句音频、关闭本句循环和逐句连播，以当前 buildId 的完整章节音频从 0 开始播放；无用户中断、网络或系统故障时持续到章末。
- 开始全文播放时清除句子“正在播放”的高亮，仅保留阅读选中状态；底部状态只描述当前整章资源。加载期间再次点击播放/暂停取消本次待播放意图，迟到授权响应不得自动发声。
- 全文模式支持暂停/继续及四档倍速；暂停后继续同一章同一构建的当前位置。自然播完显示“本章播放完毕”，保持停止，不循环、不切下一章。
- “从头播放”明确将当前章位置归零并重新播放；重复点击当前播放/暂停按钮仅切换暂停/继续，不意外回到开头。
- 点击任一句的播放按钮：停止整章音频，作废整章请求/回调，切入该句播放。点击“返回逐句”：停止整章音频并恢复进入全文前的选中句，不自动发声。全文播放期间不推测当前句，也不承诺逐句高亮跟随。
- 完整章播放不因 `needs_review / unmatched / excluded` 句子而停止；这些状态描述逐句素材，不代表整章录音损坏。真正的整章缺失、解码失败、无权限、下架或网络失败按整章错误处理。
- 手动切章立即停止当前章全文音频，取消旧请求并清除整章临时位置，进入新章的逐句待播放状态；新章需再次点击全文播放。
- 进入后台、锁屏或系统中断时仍遵守前台暂停规则，返回后不自动继续。如果阅读会话未卸载，保留整章临时秒数，用户点击继续后恢复；会话卸载/冷启动后点击全文播放从头开始。
- 媒体 URL 失效或网络失败后，保留最近确认的整章播放秒数。有效的继续/重试意图可重新授权同一资源、加载后定位该秒数再播放，不能无提示从头重播；定位失败需提示，提供“重试”和显式“从头播放”。
- 恢复定位保持 autoplay 关闭，在资源就绪后执行 seek，确认当前操作的定位完成事件及实际位置后才允许发声；默认 10 秒定位超时，实际位置与目标差值不超过 1 秒。记录来自有效播放事件的最近时间，忽略销毁/重载产生的零值；恢复误差须在 M0 长章真机测试中验证。若平台无法做到定位前静默，不得通过先从头播放再跳转掩盖失败。
- 音频仅按当前章流式加载，不提前下载全章完毕才启动，不缓存/预加载全书。不存在可用完整章文件时不偷偷切换成逐句拼接播放。

## 8. 身份、内容授权与媒体访问

### 8.1 微信登录

1. 用户点击登录/同步，阅读隐私说明并作出必要选择；游客可继续使用公开样本。
2. 前端调用 `wx.login` 得到短时 `code`，通过 HTTPS 发送给独立后端。
3. 后端调用微信 `code2Session` 换取身份，以 `(appid, openid)` 定位账号，生成内部 `userId`；不依赖一定存在 `unionid`。
4. 后端签发不可预测的业务会话 Token，客户端后续以 `Authorization: Bearer ...` 调用 API。

`wx.login` 的 code 由开发者服务端换取微信身份，这一点已通过微信官方类型声明核对。[登录接口依据](https://raw.githubusercontent.com/wechat-miniprogram/api-typings/master/types/wx/lib.wx.api.d.ts)

AppSecret、微信 `session_key`、对象存储密钥、数据库密码只存在后端；不得返回客户端、写入公开仓库或日志。客户端传入的 OpenID、userId、角色不能作为可信身份。

本地微信登录配置与排障：

- 后端从项目根目录 `.env` 或进程环境读取 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`，AppID 必须与前端微信小程序项目一致；配置修改后重启后端再获取新的 `wx.login` code。
- 缺少任意一项凭据时，`POST /v1/auth/wechat` 返回 `503 SERVICE_UNAVAILABLE`，提示“微信登录尚未配置，请先体验样本”；不得请求微信换码、生成业务会话或用模拟身份绕过登录。公开样本仍可使用。
- 微信换码请求网络失败或超时也可能返回 503，需结合响应正文区分，不能仅凭开发者工具控制台的 HTTP 状态判断为客户端版本问题。
- 本地 `.env` 不纳入 Git；可以从前端本地配置同步 AppID，但 AppSecret 只能在后端本地填写或通过环境注入，不能放到前端或要求用户在聊天中发送。缺少密钥时如实标记真实登录尚未验证。
- 回归验收覆盖分别缺少 AppID、缺少 AppSecret 的情况：返回上述明确错误，不进行微信换码，不调用会话创建。

首版业务会话默认有效 2 小时，数据库仅保存 Token 摘要、所属账号、失效时间和撤销状态；登录返回 `expiresAt`。过期后用新的 `wx.login` code 重新建会话，不把旧 code 无限重试。单次 API 流程最多自动重新登录一次，失败后提示用户；写请求只有具备幂等键才可自动重放。退出撤销当前业务会话并清除本机该账号缓存。

同一客户端同时只运行一个重新登录流程，并发 401 等待该结果；只在用户已选择登录且未退出时自动续会话。退出/切换身份递增本地身份代次，所有请求和同步操作绑定发起时的 userId 与代次，旧响应不得写入新账号缓存或触发播放。重登返回不同 userId 时按账号切换处理，不能重放原账号写请求。客户端 Token 是保存在环境隔离存储中的业务凭证，普通正文/URL 缓存规则不适用于它；退出时清除，存储失败则仅维持内存会话并说明重启后需重登。

### 8.2 权限模型

- `sample-public`：游客可读取合规样本清单、章节及签发样本播放 URL，按 IP/匿名请求限流；游客没有云进度接口权限。
- `private`：每次清单、章节、媒体授权和进度请求校验会话及有效 `book_access` 记录。登录成功不自动获得所有书籍。
- 私有内容无权访问时返回 `403 BOOK_FORBIDDEN`；不能只在 UI 隐藏入口。
- 运维通过 CLI 向内部 userId 授权/撤销，写入审计记录；不提供小程序自助提权接口。
- 客户端收到撤权/下架响应或主动登出时，停止相关播放、取消请求并清理本应用控制的私有内容内存和签名 URL；不能承诺清除微信运行时已经缓存的全部字节。首版无撤权推送：前台阅读期间每 60 秒及从后台返回时，通过 `GET /books/{bookId}/builds/{buildId}` 检查当前快照访问状态；不重复请求整章正文，不创建重复轮询。网络失败不等同于撤权，仍允许已加载内容使用，不宣称断网时能立即感知撤销。

### 8.3 媒体 URL

- 章节 API 返回句子及整章资源各自稳定的 `audioId`，不返回包内磁盘路径、对象存储密钥或长期公开地址。
- 播放前通过对应媒体授权接口取得 `url + issuedAt + expiresAt + duration`；两种模式均校验账号、书籍、构建和文件可用性，逐句额外检查句子审核状态，全文额外检查 chapterAudio 的可用状态。issuedAt 使用服务端 UTC 时间，客户端按有效期长度扣除请求耗时及后续经过时间估算剩余时效，不直接依赖手机墙上时钟；时间基准不可信时重新授权。
- 每次只授权当前要播放的一条资源（当前句或当前完整章）；不批量签发全章句子 URL，不做全书预下载。每个 URL 绑定一个资源的不可变路径。
- 逐句 URL 默认 15 分钟有效；如片段本身过长，使用 `max(900, ceil(duration / 0.75) + 60)` 秒保证慢速完整播放。整章 URL 有效期为 `max(900, ceil(duration / 0.75) + 600)` 秒，以覆盖从头开始按最慢支持倍速播放及 10 分钟余量，避免正常长章播放因固定 15 分钟时效中断。保留期构建另受第 5.3 节截止时间限制；不得悄悄截短时效后仍声称可完整播放。授权响应标记 `Cache-Control: no-store`，实际到期时间以 expiresAt 为准。
- URL 只保存在内存。新加载或暂停后继续时，如果剩余有效期不足该资源剩余播放时间（按 effectiveSpeed 计算）加 30 秒，则先重新授权；整章重新加载后恢复临时秒数。正常播放过程中不只因计时器到期就强制换源或重启。
- URL 是临时持有即用凭证，既不包含业务 Token，也不要求音频组件添加自定义 Authorization 请求头；签名值不得出现在日志或分享内容中。
- 媒体域名必须在边缘/网关逐次验证签名，缓存命中也不能绕过验证；对象存储禁止匿名读取及绕过 CDN 直链。可缓存不可变文件字节，不公开缓存授权响应。
- URL 过期或模糊网络失败时，当前操作最多自动重新授权并重试一次；播放授权 POST 只签发 URL、无进度等业务写入，可按本条重试，通用请求层不再额外重试它。如果已暂停、换句/换章、切模式、退后台或失去权限，禁止自动续播。全文重试保持已确认时间位置，再次失败交给用户重试。
- 下架/撤权后立即停止签发新 URL；已签发 URL 可能在自身 expiresAt 前仍可请求，逐句通常约 15 分钟，超长片段及整章按上述时长公式确定。已开始传输或已缓存的字节不能远程收回。本方案不是 DRM，不能宣称完全防复制。
- 媒体服务支持 HTTPS、`audio/mpeg`、Content-Length、HEAD 和单区间 Range。无 Range 的 GET 返回 200；合法且可满足的闭合/开放末尾/后缀字节区间返回 206 及正确 Content-Range；合法但不可满足的区间返回 416 及 `Content-Range: bytes */总长度`。HEAD 返回元数据且无正文、忽略 Range；未知单位或首版不支持的多区间可忽略并返回完整 200，畸形字节区间统一拒绝为 400，不能笼统将所有 Range 情况都定义为 416。[HTTP 语义依据](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)
- GET/HEAD 和每次分段请求均先鉴权；最终音频域名也必须在平台允许范围内，不依赖携带临时 URL 的跨域跳转、第三方 Cookie 或可绕过的 Referer 作为唯一鉴权手段。M0 验证所选存储/CDN 的签名算法、最大有效期、HEAD/Range 与长章策略兼容；不兼容时调整网关实现并记录验证结果。

## 9. 前后端 API 契约

### 9.1 通用约定

- API 基址由环境配置，例如 `https://api.example.com/v1`；文内 example.com 仅为占位域名。
- 请求/响应为 UTF-8 JSON；时间用 UTC ISO 8601，音频时长为秒；身份字段为不透明字符串，不转成数字。
- 成功返回 `{ "data": ..., "requestId": "..." }`；失败返回 `{ "error": { "code": "...", "message": "...", "details": {} }, "requestId": "..." }`，并使用正确 HTTP 状态码。
- 客户端忽略向后兼容的新可选字段；未知关键版本/审核枚举应拒绝播放。破坏性变更升级 API 主版本。
- API 不返回任意可执行 HTML；文本仅供展示。错误不包含服务端路径、SQL、密钥或堆栈。
- 默认请求超时 10 秒；GET 仅对网络失败/5xx 最多自动重试一次。429 按 `Retry-After` 提示等待；401/403/409/422 不作普通网络重试。
- 请求体默认限制 64 KiB，云进度载荷限制 4 KiB，限制字符串长度；对 bookId 等 ID 使用白名单字符和长度约束，不把用户输入拼接成路径或查询语句。
- bookId/chapterId/sentenceId 沿用输入 Schema 的 `^[A-Za-z0-9][A-Za-z0-9_-]{0,95}$`；buildId/textRevision 沿用 v2 非空字符串语义，作为路径段或查询值正确编码，不额外套用更窄的 ID 正则而拒绝合法旧包。实施时在 OpenAPI 中明确各字段长度和资源上限；超限导入须报告具体原因，不静默截断正文或身份。路径安全仍由服务器生成对象键和第 4.1 节规则保证。
- `version/expectedVersion` 为非负安全整数；`clientMutationId` 为每次逻辑写入新生成的 UUID，重试沿用。PUT/reset 使用严格请求 DTO，拒绝未知写字段；幂等摘要包含方法、书籍路径、正文版本及规范化正文（含 expectedVersion），避免不同接口或书籍误共用一个结果。

### 9.2 接口清单

所有下列业务路径都相对 `/v1`。内容接口访问规则依据书籍的 `sample-public / private` 可见性。

| 方法与路径 | 关键输入 | 结果/要求 |
|---|---|---|
| `POST /auth/wechat` | `{code}` | `{accessToken, expiresAt, user:{id}}`；请求/响应不缓存 |
| `DELETE /auth/session` | 当前会话 | 撤销当前 Token；客户端清理账号缓存 |
| `GET /me` | 会话 | 内部 userId、同步状态需要的基本信息；不返回 OpenID |
| `GET /books?audience=sample|member&limit=20&cursor=...` | 默认 sample；member 需登录；cursor 可省略 | `{items: BookSummary[], nextCursor}`；仅返回该分类内已发布且当前可访问的书籍，空列表返回 200 |
| `GET /books/{bookId}` | 选中的书籍 ID | 返回该书活动构建的完整书籍 DTO，用于首次进入目录和重新进入时解析快照；无权访问不得静默切换书籍 |
| `GET /books/{bookId}/builds/{buildId}` | 固定快照 | 该构建的书籍和全章目录；只有可读构建可访问 |
| `GET /books/{bookId}/builds/{buildId}/chapters/{chapterId}` | 固定快照 | 完整当前章、句子、审核状态及 audioId |
| `POST /books/{bookId}/builds/{buildId}/sentences/{sentenceId}/playback` | 无正文载荷 | `{audioId, url, issuedAt, expiresAt, duration}`；不可播放句拒绝 |
| `POST /books/{bookId}/builds/{buildId}/chapters/{chapterId}/playback` | 无正文载荷 | `{audioId, url, issuedAt, expiresAt, duration}`；仅签发当前构建的完整章节音频，无可用整章资源则拒绝 |
| `GET /me/progress/{bookId}?textRevision=...` | 会话、正文版本 | `{version, progress}`；未建立记录时 version 为 0、progress 为 null；墓碑为 version > 0、progress 为 null |
| `PUT /me/progress/{bookId}` | 第 10 节写入结构 | 校验、条件写入并返回 `{version, progress}` |
| `POST /me/progress/{bookId}/reset` | `{textRevision, expectedVersion, clientMutationId}` | 条件清空位置并保留递增版本墓碑；返回 `{version, progress:null}` |
| `GET /health/live` | 无 | 仅服务存活，不返回内部信息 |
| `GET /health/ready` | 内部监控访问 | 数据库/必要配置就绪；失败返回 503 |

书架使用列表接口，进入目录使用 `GET /books/{bookId}` 解析当前活动快照；进入阅读后仍按 `bookId/buildId` 显式查询，不能随活动指针暗中换源。1.3 取代尚未实现的 `/books/current` 设计，不要求维护该单书接口。除两个健康检查外，未列出的管理写接口不属于小程序公共 API。

列表按 bookId 升序使用游标分页，limit 默认为 20、最大 50，nextCursor 为 null 表示结束。游标为不透明值，绑定 audience 与查询身份，跨分类/身份复用或非法游标返回 `400 INVALID_REQUEST`；它不代替访问授权，每页都重新过滤权限。刷新从第一页开始，后续页按 bookId 去重；分页期间新增的较早条目可在刷新后出现，不承诺列表跨请求的全局快照。只有存在 active 构建的书籍参与列表；对已获权的指定书籍，若无活动构建则详情返回 `503 CONTENT_UNAVAILABLE`，提供回书架入口。

### 9.3 内容 DTO

`BookSummary` 包含 `bookId, buildId, textRevision, title, language, edition, contentScope, visibility, chapterCount, contentChapterCount, sentenceCount, playableCount, chapterAudioAvailableCount`。计数来自该条目同一活动构建；contentChapterCount 只计有句子的章节，chapterAudioAvailableCount 只计其中整章音频 available 的章节。两者相等且大于 0 才显示全部章节可用，部分可用要求大于 0 且小于 contentChapterCount；其余显示暂不可用。列表不返回 chapters、正文、进度或媒体 URL，也不逐本触发客户端进度查询；进入具体书籍或继续学习时再获取它的进度。

书籍 DTO 字段：`bookId, buildId, textRevision, contentScope, title, language, edition, visibility, chapters[]`；每章包含 `id, title, sentenceCount, playableCount, duration, chapterAudioStatus`，数组决定顺序，不暴露输入包的 `data` 路径。chapterAudioStatus 为 available 或 unavailable，便于显示全文能力。

章节 DTO 字段：`bookId, buildId, textRevision, chapterId, chapterDuration, chapterAudio, sentences[]`；句子包含 `id, index, text, duration, alignment, audioId`，可选 `sourceText`。不可播放句的 `audioId/duration` 为 null，可播放句必须有值。`timing/sourceTiming/padding` 留给导入报告，不作为前端播放依赖。DTO 是明确转换后的 API 表达，不能把输入包 JSON 原样混入后再要求小程序猜路径。

API 的 `chapterAudio` 始终存在，字段为 `status, audioId, duration, reasons`；available 时 audioId/duration 非空且 reasons 为空，unavailable 时二者为 null 且有原因。后端把输入包的可选 chapterAudio 转换为此结构，不把输入路径 audio 返回给小程序，也不在章节 DTO 中提前签发播放 URL。

当前章一次返回完整正文，以保持本章搜索语义；界面可分批渲染。没有完整载入时搜索显示加载状态，不把当前渲染片段误当全章。

### 9.4 错误码与前端动作

| HTTP / code | 前端动作 |
|---|---|
| 400 `INVALID_REQUEST` / `LOGIN_CODE_INVALID` | 显示输入错误；登录 code 失效需新取 |
| 401 `SESSION_EXPIRED` | 有界重新登录；失败后保留未同步本地进度 |
| 403 `BOOK_FORBIDDEN` | 停止私有音频、清理内容缓存、显示未授权 |
| 404 `BOOK_NOT_FOUND` / `BUILD_NOT_FOUND` / `CHAPTER_NOT_FOUND` / `SENTENCE_NOT_FOUND` | 停止相关操作，提供回目录/刷新入口；未发布构建按不存在处理 |
| 409 `BUILD_UPDATE_REQUIRED` | 保留阅读位置，提示旧构建即将到期，由用户选择加载新版本，不自动换源发声 |
| 409 `PROGRESS_CONFLICT` | 展示本机与云端位置，按第 10 节解决 |
| 409 `IDEMPOTENCY_KEY_REUSED` | 同一个幂等键携带不同载荷，拒绝写入并上报客户端错误 |
| 410 `BUILD_RETIRED` / `BUILD_REVOKED` | 停止该构建播放，提示更新/内容下架 |
| 422 `SENTENCE_UNPLAYABLE` | 保留原文与原因，不申请其他音频冒充 |
| 422 `CHAPTER_AUDIO_UNAVAILABLE` | 显示整章音频不可用原因；保留逐句阅读，不以逐句连播冒充全文播放 |
| 422 `PROGRESS_INVALID` | 保留现有进度；提示正文版本、句子或速度非法 |
| 429 `RATE_LIMITED` | 显示等待时间，禁止密集重试 |
| 503 `CONTENT_UNAVAILABLE` / `SERVICE_UNAVAILABLE` | 可重试错误，不显示空数据假装成功 |

私有正文/进度响应使用 `Cache-Control: private, no-store`，由客户端控制内存缓存；服务端可以缓存构建级数据，但每次请求仍执行用户授权。首版不引入 ETag/304 状态以简化契约。

账号书架响应同样使用 `Cache-Control: private, no-store`，不得将 A 用户的可见书籍列表缓存后返回给 B 用户；公开样本列表与私有列表分开查询及缓存。

先验证会话及书籍访问权，再向有权限的请求报告构建/句子状态，避免通过不同错误响应枚举私有内容。客户端只对当前身份代次、资源和请求仍有效的错误执行清缓存/定位操作，旧请求的迟到错误不能打断新账号或新构建。

## 10. 阅读进度、本地保存与跨设备同步

### 10.1 进度定义

进度代表最近选中的句子和速度偏好，不代表已学会、已听完或学习时长。不可播放句也可作为阅读位置；空章节不生成新的句子进度，保留上次有效位置。

云进度唯一键是 `(userId, bookId, textRevision)`。记录包含 `chapterId, sentenceId, preferredSpeed, sourceBuildId, updatedAt` 及服务端并发 `version`。不保存句内秒数、搜索词、循环或连播模式。

写入请求示例：

```json
{
  "textRevision": "sample-text-v1",
  "sourceBuildId": "sample-build-001",
  "chapterId": "c01",
  "sentenceId": "c01-s0001",
  "preferredSpeed": 1.25,
  "expectedVersion": 7,
  "clientMutationId": "9d026816-0ff2-4c3c-8654-9197563421ae"
}
```

新的 PUT 写入只允许四档速度，校验书籍授权、正文版本、可读构建和章节/句子归属；`sourceBuildId` 用于验证，不作为进度唯一键。GET/reset 可操作该用户已保留的历史正文进度，不要求旧媒体构建仍可读，reset 不得创建未知正文版本。服务端生成 `updatedAt`，客户端时钟不参与覆盖优先级；已成功写入的重放顺序见第 10.4 节。

成功示例：

```json
{
  "data": {
    "version": 8,
    "progress": {
      "bookId": "sample-en",
      "textRevision": "sample-text-v1",
      "sourceBuildId": "sample-build-001",
      "chapterId": "c01",
      "sentenceId": "c01-s0001",
      "preferredSpeed": 1.25,
      "updatedAt": "2026-09-17T03:00:00Z"
    }
  },
  "requestId": "req-example"
}
```

### 10.2 本地保存

- 使用小程序存储 API，键包含环境、内部 userId（游客为独立 guest 命名空间）、bookId、textRevision；账号之间不复用进度。
- 每本书的位置、速度偏好、云版本和待同步队列独立保存，切换或清除一本书不影响其他书籍。另按环境及身份保存 `lastReadBookId`，仅在该书产生实际学习操作时更新，用于本机最近阅读入口；该标记不参与云端进度冲突，不保存正文或签名 URL，也不承诺跨设备同步“最近打开哪一本书”。该书有本机位置但无云确认时，入口须如实显示待同步状态。
- 每次用户切句、改速或切章后选中有效句，以及逐句连播推进时，立即更新本地缓存。缓存包含本地格式版本、递增 localRevision、最后确认云快照及 version、待同步变更的 baseVersion、不可变在途请求及原幂等键；以一个完整存储值落地，避免位置与版本分别写入后错配。恢复时校验结构，损坏或未知格式提示无法恢复，不能直接提交。
- 初次加载默认位置、恢复云进度、内容版本回退定位及清除后的界面定位都不产生脏写入；没有用户学习操作时不得把云端位置或墓碑自动改写成第一句。只确认已落地的 localRevision，不将服务器成功响应误认为较新的本机修改也已保存。
- 本地写失败时继续提供阅读播放，显示“本机保存不可用”；已登录且网络正常仍可同步到服务端，不假报已保存。
- 未同步本地操作最多保留 7 天的自动重试资格；超期保留位置但标记需用户重新选择同步方案，不自动提交陈旧写入。
- 当前快照、最多最近 3 章正文及签名 URL 仅内存缓存；首版不持久化私有正文或主动下载音频。
- 断网仅保证已加载正文仍可阅读，当前已缓冲音频可能继续；切句所需授权/媒体未取得时显示需联网，不承诺离线播放。

### 10.3 同步时机和队列

- 登录/进入书籍时拉取云进度；没有本地待同步修改时可验证并恢复云端位置，不自动播放。已有修改必须保留它产生时的 baseVersion；GET 得到更高版本时按冲突处理，不能把新版本号塞入旧修改后直接提交。有结果未知的在途写入时，先按原载荷/原幂等键重试确认，再处理云快照及后续修改。
- 从未成功读取云记录时 baseVersion 为“未知”，不能假定为 0；先读云端，再按首次导入/冲突规则选择。只接受当前请求代次的云响应，低于已确认 version 的迟到 GET 不得回退状态。
- 本地变化后 2 秒防抖提交，持续切句时最迟 10 秒尝试一次；这些是产品同步策略，不代表后台能继续执行定时器。
- 切章、离开阅读页和应用退后台时尝试提交已落地本地记录；冷启动、网络恢复、回前台时继续处理待同步记录。
- 每个进度键最多一个在途请求，后续位置合并为下一次最新快照；已经发出的载荷和幂等键保持不变。
- 成功响应只确认它对应的本地版本；如果用户已经继续切句，不把旧响应位置写回 UI。排在本机前次写入之后的修改，可将 baseVersion 推进到该次成功响应的 version 再提交；未经用户选择，不能使用其他 GET/冲突响应中的较新版本替换其基线。
- 写请求只在网络失败/5xx 时进行有界重试，首次请求失败后间隔 1/2/4 秒，最多追加三次；通用网络层不额外重试。之后显示“待同步”，等待明确的网络恢复/前台/手动同步事件再尝试；这些事件也不能修改原请求的幂等键、载荷或 baseVersion。401 的共享重登及 429 的等待规则另行适用，但不能越过 7 天自动重试期限。
- 云端明确返回成功才显示“已同步”；离线缓存成功只能显示“已保存在本机，待同步”。

### 10.4 并发控制、幂等与冲突

1. 无记录时 `GET` 返回 `version: 0, progress: null`；首次写入要求 `expectedVersion = 0`。
2. 所有写入在数据库事务中执行比较并更新：当前版本等于 `expectedVersion` 才可落地，成功后 `version + 1`。两个首次写入并发时也只能有一个成功；使用唯一约束及原子条件写入保证，另一个返回 PROGRESS_CONFLICT，不暴露数据库重复键 500。
3. `(userId, clientMutationId)` 唯一；服务端对载荷计算摘要。完全相同的请求重试返回首次结果、不重复加版本；同键不同载荷返回 `409 IDEMPOTENCY_KEY_REUSED`。
4. 每次先校验当前会话、账号及书籍权限，再查幂等结果；命中同载荷成功记录后返回首次业务结果，即使其 sourceBuildId 已退役，也不重做构建校验或版本比较。未命中时才校验新写入的资源及 expectedVersion；幂等结果与进度更新原子提交。记录至少保留 30 天，覆盖客户端自动重试窗口；并发同键请求只落地一次。失败或回滚事务不缓存为成功，错误中的冲突快照可以随后重读。
5. 版本不一致返回 `409 PROGRESS_CONFLICT`，`error.details` 包含当前 `{version, progress}`。不按手机时间、最高句序或最后到达请求静默覆盖。
6. UI 显示“本机：章节/句子”和“云端：章节/句子”，让用户选择“使用云端”“保留本机并同步”或“稍后处理”。时间只作参考。
7. 选择云端：停止播放、清理该键待同步操作，验证并定位云端句子，不自动播放。若云端为墓碑，显示“云端已清除”，本地同步为空记录，界面可停在首个有效句但不自动写回；偏好速度恢复默认 1×。
8. 选择本机：使用刚返回的云版本与新的幂等键提交当前位置；若再次冲突重新提示，不强制覆盖。
9. 选择稍后：允许继续本机学习，保留待同步状态，暂停自动云写入以免反复弹窗。

### 10.5 版本变化、登录合并与清除

- 同正文版本换音频构建：在新构建校验句子存在后保留位置；不要求旧音频构建仍可下载。
- 正文版本改变：提示旧进度不兼容，进入第一章第一句；保留旧版本云记录，不按序号迁移。回退到旧正文时可恢复其独立进度。
- 云进度涉及的章节或句子在当前构建不存在：提示内容不一致，回到首个有效阅读位置，不偷偷猜相邻句。
- 待同步记录的旧构建已失效时，先按第 10.4 节确认结果未知的旧请求；只对明确未成功的写入改用活动构建。正文版本相同且句子验证通过后可生成新载荷/新幂等键，但沿用原 baseVersion；新读到的云版本若不同仍需用户解决冲突。超过自动重试期限则先让用户选择同步方案。不能因换 buildId 自动提升 expectedVersion，或替换已发出载荷后沿用旧键。
- 游客登录同一本书且同一正文版本时先读取云进度；version 为 0 时可询问是否保存游客位置，双方都有位置则沿用冲突选择。progress 为 null 但 version > 0 表示已清除，必须显示此事实，经明确选择后才可导入游客位置。不能把 A 书游客进度写进 B 书，也不能跨 textRevision 合并。
- 设置页操作命名为“清除本书当前正文版本进度”，确认框展示书籍、正文版本及“当前账号所有设备的位置与速度偏好，其他正文版本保留”；历史版本删除走数据删除渠道。登录用户在线调用 reset，服务端将该正文记录置空并递增 version，保留墓碑，不能物理删除后把版本重置为 0。
- 从书架进入设置且尚未选择书籍时，清除进度需先选择并展示目标书籍及正文版本，不能把无上下文的“清除”解释为清除全部小说；成功清除该键后，移除引用该位置的本机继续学习入口，其他书的位置仍保留。
- reset 与该键 PUT 共用串行队列。用户确认清除时停止播放并冻结云写入，取消尚未发出的本地变更；结果未知的旧 PUT 先用原键确认，然后以已确认版本提交 reset。reset 遇到其他设备的新版本仍需重新确认，不静默清除。reset 完成后丢弃旧代次响应、保留墓碑版本并解除冻结；清除处理中可阅读，但不允许产生新的可同步位置/改速操作，UI 明确显示待确认与重试。
- 另一设备持旧版本写入清除后的记录时产生冲突，不能自动复活已清除进度。reset 也使用幂等键及条件版本；网络不确定时显示待确认，不假报云端清空成功。
- 游客清除只作用于本机。退出账号先提示存在的未同步变更，可重试同步或由用户选择退出；不把未同步数据提交给下一登录账号。
- 断网退出可立即清除本机会话和数据，但远端 Token 撤销可能未完成，直到服务端撤销成功或会话到期才失效；界面不把本地退出描述为已完成所有设备登出。

### 10.6 全文播放的位置边界

- 整章播放秒数是当前阅读会话的内存状态，键为 bookId/buildId/chapterId；用于暂停、短暂中断和同资源重试，不写入句子级云进度。
- 播完整章不把句子进度改成章末，不假报全章已学完；全文期间不根据音频秒数推测句子 ID，不覆盖进入全文前的阅读位置。
- 倍速偏好继续使用现有保存/同步机制；已有有效句子进度时只改 preferredSpeed，保留句子位置。没有有效句子时仅保留本机速度偏好，不伪造句子记录。
- 离开并卸载阅读页、切章、换构建或退出账号时清除整章临时位置；冷启动后全文从 0 开始。跨设备整章断点续听与可拖动时间进度条不属于本次新增要求。

## 11. 服务端数据模型与模块

### 11.1 逻辑数据表

以下为目标逻辑模型，实施时生成数据库迁移；本次不创建数据库。

| 表 | 关键字段与约束 |
|---|---|
| `users` | 内部 id、appid、openid、状态、创建时间；`(appid, openid)` 唯一，OpenID 不对外暴露 |
| `sessions` | token_hash、user_id、expires_at、revoked_at；token_hash 唯一，支持按用户撤销 |
| `books` | book_id、创建后不变的可见性、可空 active_build_id；非空时必须属于本书且处于 active 状态 |
| `book_builds` | `(book_id, build_id)` 唯一；text_revision、content_scope、包摘要、第 5.3 节状态、发布/保留截止时间、最后签名到期时间、标题/语言/版本信息 |
| `chapters` | `(book_id, build_id, chapter_id)` 唯一；sort_order、标题、计数、源时长、chapter_audio_status、chapter_audio_id、不可用原因；构建内 sort_order 唯一 |
| `sentences` | `(book_id, build_id, sentence_id)` 唯一；chapter_id、index、text、source_text、alignment、duration、audio_id；章内 index 唯一 |
| `audio_assets` | audio_id、kind（sentence/chapter）、所属书籍/构建/章节、可空 sentence_id、私有 object_key、字节数、hash、duration；一条可播放句或一个可全文播放章节各对应一个成品对象 |
| `book_access` | `(user_id, book_id)` 唯一；生效/失效时间、撤销状态；不以客户端角色字段授权 |
| `reading_progress` | `(user_id, book_id, text_revision)` 唯一；句子位置、偏好速度、source_build_id、version、updated_at、reset 标记 |
| `progress_mutations` | `(user_id, client_mutation_id)` 唯一；请求摘要、响应快照、创建/过期时间，与进度更新同事务 |
| `content_audits` | 管理员标识、操作、书籍/构建、摘要、时间；覆盖导入、发布、回退、撤权 |

章节和句子通过组合外键确保属于相同构建；`audio_assets` 不能跨构建误关联。句子本身允许不可播放，不允许给这类句子建立可签发音频引用。状态和可空值组合在业务校验中检查，并为可表达的约束添加数据库 CHECK。

整章资源 kind 为 chapter、sentence_id 必须为空，且在同一 book/build/chapter 下唯一；逐句资源 kind 为 sentence，必须关联本章合法句子，并按 book/build/sentence 唯一。章音频可用状态约束其 chapter_audio_id 和原因，与句子审核状态独立；不可因某个句子缺失而自动删除完整章资源。

进度不绑定到会随资源保留策略删除的音频对象；历史正文版本/句子身份索引保留到相关进度清理完成。删除旧 MP3 不能级联删除学习进度。清空进度时位置字段置空，保留版本号与正文键。

### 11.2 索引、事务与访问

- 身份查找、Token 摘要、有效授权和进度唯一键具备索引；外键引用侧及章节排序查询按实际访问建立必要索引，避免每次请求全表扫描。
- 章节查询按书籍/构建/章节取完整有序句子，一次查询或有界批次完成，避免逐句查音频的 N+1 请求。
- 发布指针切换、条件进度更新与幂等记录必须是短事务；对象上传、微信换码和媒体网络探测放在事务外。
- API 使用连接池和最小权限数据库账号；迁移/导入使用单独运维身份，普通 API 账号不能任意改表。
- 所有用户进度查询从已验证会话取 userId；客户端提供的路径/参数不能覆盖这一条件。
- 模块建议：`Auth / Books / Playback / Progress / Import / Storage / Health`，保持单体独立 API 服务即可。

## 12. 加载、缓存、性能与故障恢复

### 12.1 加载策略

- 书架首页只加载当前分类的第一批书籍摘要；有最近阅读标记时最多额外查询该书详情与进度，不逐本拉取章节、进度或预创建音频对象。点击书籍后才加载其章节目录，点击章节后才加载正文。
- 进入阅读后加载完整当前章到逻辑层，分批将可见句子送入渲染层；避免每次高亮变化传输整章数据。
- 以现有最长章 593 句及扩展 1,000 句样本测试；确有必要再采用虚拟列表，必须保持搜索、定位和读屏可用。
- 书架内存缓存按环境、用户/游客及 audience 隔离；退出清除私有列表。章节内存缓存键包含用户、书籍及构建身份，全应用合计最多 3 章；退账号、切正文或撤权清空相关缓存。
- 本地进度缓存不是版权内容下载；代码包中只包含界面和少量明确可分发样本，不携带整本真实音频或原书。
- 微信更新提示不得在播放中强制重启；先保存位置，由用户在合适时机更新。

### 12.2 首版性能目标

以下是待验证目标，不是已完成的测量结果。基准为预先记录的 Android/iOS 真机、稳定网络（下行不低于 10 Mbps、RTT 不高于 100 ms）、已登录、资源未预加载，连续至少 30 次取 p95：

| 指标 | 目标 |
|---|---|
| 书架发起业务请求至首批书籍可操作 | <= 2 秒，不包含微信自身启动和用户交互登录耗时 |
| 点击书籍至该书章节目录可操作 | <= 2 秒，不因其他书籍加载情况阻塞 |
| 点击章节至首屏正文可操作 | <= 2 秒 |
| 点击句子至首个可听声音，含签名和媒体加载 | <= 2 秒 |
| 点击全文播放至当前章首个可听声音，含签名和流式加载 | <= 2 秒，不等待完整章文件下载结束 |
| 593/1,000 句章节搜索输入到结果 | <= 300 ms |
| 普通 JSON 读接口（不含微信换码和媒体传输） | 50 并发下 p95 <= 300 ms，错误率 < 1% |

性能报告同时列出冷/热缓存、网络条件、设备/微信/基础库版本、服务部署规格与样本量。弱网可以超过目标，但必须有真实加载、超时和恢复状态，不用固定延迟伪造完成。

### 12.3 故障边界

- 配置/书籍清单错误：阻止进入阅读；章节 DTO 错误：仅阻止该章并允许回目录；单句文件错误：仅停止该句和逐句连播；整章音频错误：仅停止全文模式，仍允许有效的逐句功能。
- 断网、401、403、内容撤销与普通解码失败分别提示，不能统一显示“网络差”。
- 网络恢复后可重试当前选中句，但必须由有效用户播放意图或手动操作触发，不恢复退后台前的自动播放。
- 存储写入失败、服务端不可用或微信登录失败不妨碍已加载样本阅读；私有新内容请求仍须正常鉴权。
- 记录带 requestId 的错误、业务错误码、书籍/构建/章节/句子 ID 和耗时；不得记录完整正文、Token、签名 URL 查询串、登录 code 或 session_key。

| M0 契约与平台验证 | 冻结 v2 输入及整章扩展/API/进度模型；搭小程序音频最小验证页 | iOS/Android 测试逐句/长整章 MP3、四档速度、模式切换、后台暂停与恢复定位；记录依赖版本 |

| M2 小程序核心 | 书架、章节目录、阅读页、逐句/全文播放器、搜索、异常状态、本地进度 | 使用 Mock 和真实样本服务完成选书/换书/继续学习及核心流程，整章一次播至章末，无叠音或旧回调污染 |

| M4 内容联调与发布 | 受控真实内容导入、更新/回退、性能优化和部署文档 | 第 15 节验收满足；内容授权与正式平台配置落实 |

界面实施前产出书架、章节目录、阅读、播放中、不可播放和弱网状态设计；书架的视觉实现与呈现验收交由 `ui-design` 阶段，文案细化交由 `copywriting` 阶段，本规格约束其行为与状态。优先完成可验证的小程序音频原型，平台验证不依赖真实全书处理完成。全过程不要求安装 GPU、重新选择对齐模型或改造上游音频流水线。

## 15. 验收标准

### 15.1 前端与播放

- 样本可独立完成章节浏览、逐句播放/暂停、原文导航、循环/连播互斥、全文播放、四档速度和搜索。
- 快速连续点击至少 20 次、加载中取消、切章、重试、离页/退后台后，最后意图唯一有效，无叠音、无旧句高亮、无自动误发声。
- 连播遇不可播放句、缺文件、授权失败或章末停止；循环仅重复本句；速度实际生效。
- 空章、空搜索、长句、待复核、未知状态、错误 DTO、缺文件、解码失败均有对应行为。
- 搜索期间播放不变，导航仍按原文；底部当前句不随过滤消失。
- 新启动、恢复进度、更新内容、登录恢复、冲突选择和从后台返回均不自动发声。
- 关闭本地存储/模拟写失败仍可播放，并准确显示保存状态。
- 媒体授权、canplay、seeked 尚未返回时暂停/退后台/退出，迟到成功事件不能发声；播放中断网且无明确 error 回调时，缓冲超时仍会生效，重试次数不叠加。

### 15.2 服务端、契约与内容版本

- 前后端独立安装、启动、构建；前端对接 Mock 可工作，后端用 HTTP 测试客户端可验证，无数据库直连或前端密钥。
- 正常 v2 包导入成功，缺少整章扩展的旧包标记全文不可用；整章 available 却缺文件/时长超差或扩展非法时拒绝导入。未知版本、混合 buildId、重复 ID、非法路径/越界链接、错误计数和逐句状态冲突同样拒绝。
- 相同构建重复导入幂等、同 ID 不同包拒绝；导入/上传失败不改变在线版本。
- 发布/回退原子切换；正在阅读旧版本时不混用新 JSON/音频；正文变化和版本失效提示正确。
- 游客只能访问公开样本；未授权账号不能读取私有正文、签发其音频或读写他人进度；修改资源 ID 不能越权。
- 签名过期、篡改、撤权、访问源站直链和 CDN 热缓存命中均执行正确的访问规则；Range 的 206/416 正常。
- staged/ready 不可被普通用户读取；retained 到期、即将到期的长音频授权、活动构建撤销及并发发布符合第 5.3 节；对象清理不早于既有 URL 到期，不误删可回退资源。
- 书架按公开样本/账号授权过滤，样本入口不会公开同 bookId 的私有历史构建；无推送情况下按轮询/重新请求发现撤权，断网及既有 URL 的限制如实展示。
- 相同内容文件在不同机器/文件时间下产生相同包摘要；引用音频字节改变、校验后被替换都能发现。HEAD、无 Range、开放末尾/后缀 Range、非法/多区间按第 8.3 节返回，错误与缓存命中不绕过鉴权。

### 15.3 进度与同步

| 场景 | 通过条件 |
|---|---|
| 同账号两设备 | A 成功同步后 B 读取到相同正文版本的位置和偏好速度，不自动播放 |
| 不同账号/游客切换 | 进度、本机缓存、云写入及授权内容互不串用 |
| A 离线、B 已更新 | A 恢复网络得到冲突；未经选择不覆盖 B |
| 服务端已写但响应丢失 | 原幂等键重试返回原结果，只增加一次版本 |
| 同幂等键不同载荷 | 拒绝并报告错误，不静默修改进度 |
| 在途请求后用户继续切句 | 迟到响应不把界面和本地位置回退 |
| 本文不变、仅音频构建更新 | 校验句子后保留进度 |
| 正文版本改变 | 明确提示不兼容，旧记录独立保留，不按序号推测 |
| 清除云进度后旧设备重连 | 版本墓碑触发冲突，不能自动复活旧位置 |
| 本地存储失败/离线/服务超时 | 不假报同步成功，提供明确恢复入口 |
| 冷启动/恢复默认位置/采用云端墓碑 | 不产生自动 PUT，不将第一句或旧位置重新写回云端 |
| 从未读取云端即离线学习/迟到 GET | 未知基线不当作 0；旧响应不回退已确认版本，已有云位置需明确合并 |
| 旧构建失效同时另一设备已更新 | 换 sourceBuildId 后仍保留原 baseVersion，必须提示冲突 |
| 已成功写入但构建随后退役 | 相同请求重放仍返回首次成功结果；权限已撤销时拒绝泄露该结果 |
| 两个 version=0 写入或同幂等键同时到达 | 首次写入只成功一次；分别返回业务冲突或相同成功结果，无重复键 500 |
| 清除时旧 PUT 在途且结果未知 | 先确认旧请求再 reset；旧响应不恢复界面或再次入队，其他设备新写入需重新确认 |
| 多个 401 与退出/账号切换交错 | 一次共享重登；旧身份的进度、错误和播放响应不能影响新身份 |
| 墓碑与游客进度相遇 | 明示云端已清除，未经选择不导入；不同正文版本不合并 |

### 15.4 真机与发布环境

- 至少一台 iOS 和一台 Android 手机在真实微信内验收，记录机型、系统、微信、基础库、构建版本；同时测最低支持基础库与当前稳定基础库。
- 开发者工具仅用于辅助，不能代替真实音频、倍速、弱网、蓝牙/耳机、静音开关、锁屏、来电中断和前后台测试。
- 代表性窄屏/大屏、底部安全区、键盘弹起、长章节滚动和系统读屏通过。
- 在启用正式域名校验、HTTPS 和真实后端的测试/体验版上完整走通；样本与私有内容权限分开验证。
- 执行第 12 节性能测量、后端 50 并发检查、一次内容回退和数据库恢复演练，记录实际结果。
- 没有目标设备或发布资质时明确标为未验证/未满足，不把模拟器结果或文档完成等同于上线完成。

### 15.5 内容联调

先用合规短样本验收应用，再在明确授权环境验证真实首章：章首/章末、短句/长句、对话、待复核和录音缺句。检查文字与输入包一致、句子和片段一一对应、诊断计数准确。截音/文本质量问题反馈音频项目修复并重新导出。

全书到位后单列 17 章导航、最长章性能、代表性播放与剩余内容问题；应用功能通过不替代全书语义/截音质量检查。

### 15.6 全文播放验收

| 场景 | 通过条件 |
|---|---|
| 当前章从头播放 | 一次点击全文播放，从该章完整音频 0 播至结尾，过程中无需逐句操作，不跨章、不自动循环 |
| 章节含不可播放句 | 整章音频独立可用时连续播放，不被逐句 needs_review/unmatched/excluded 状态截断 |
| 逐句与全文互切 | 即时停止旧模式，无叠音；旧授权/ended 回调不能改写新模式或启动其他句子/章节 |
| 暂停、继续、从头播放、倍速 | 继续保持秒数，从头播放归零；四档实际生效，控制文字与当前模式一致 |
| 本章搜索/手动切章 | 搜索不缩短全文播放范围；切章立即停止旧章，新章不自动发声 |
| 长章节与 URL 时效 | 使用实际长章至少完成一次 0.75× 全程播放，超过 15 分钟仍不因固定时效失败；签名响应符合整章时效规则 |
| URL 失效、断网及重试 | 同章同构建从最后确认时间恢复；定位失败明确提示，不无提示重头播放、不无限重试 |
| 后台、锁屏、系统中断 | 暂停且返回不自动播放；未卸载会话手动继续可恢复秒数，冷启动从头 |
| 阅读进度隔离 | 全文结束不覆盖原句子位置、不标记全部学习完成；速度偏好保存正常 |
| 旧包/缺失整章音频 | 全文按钮禁用并说明原因，合法逐句功能仍可用，不退化成拼接音频冒充全文 |
| 权限和内容回退 | 章节授权接口不能越权；换构建后不复用旧整章资源或临时秒数 |
| 恢复定位中的暂停/切模式 | 定位前无声音，取消后 seeked 不触发播放；10 秒定位超时及 1 秒误差目标有真机记录 |
| 手机时间错误/旧构建临近退役 | URL 时效不依赖手机绝对时间；不足完整播放窗口时明确提示更新，不反复换 URL |

全文模式必须在 iOS 和 Android 真机验证；全书全文播放验收须确认每个有内容章节的完整音频及授权状态，现有逐句音频统计不能作为整章资源已经就绪的证明。

### 15.7 书架与多书扩展验收

- 使用至少两本不同 bookId 的原创/获授权测试包，故意复用 c01、c01-s0001 等章句 ID，验证选书、返回、跨书切换后内容、速度偏好及待同步队列独立；不要求为此提前准备其他真实小说。
- 一次新书导入、发布及授权后，通过书架刷新即可访问；无需重新构建小程序。一本书发布、回退或撤销不改变另一本书的活动构建或进度。
- 覆盖游客、已登录无授权、两用户拥有不同书籍权限、0/1/多本、长书名、无封面及读屏选书；接口和 UI 均不泄露未授权私有书籍元数据。
- 使用至少 51 条测试摘要验收分页、去重、分页失败重试及刷新；游标跨账号/分类复用被拒绝，加载更多失败不清空已有条目。
- 书架点击进目录，继续学习到合法阅读位置，均不发声；逐句和全文播放期间返回书架/切书立即停止旧音频，迟到响应不得恢复旧书播放或覆盖新书进度。
- 无返回栈直达阅读页仍可回到目录/书架；最近书籍不在首批列表、已撤权、已下架或正文变化时均有明确恢复路径。
- 书架首次加载不请求全书章节或为每本书查询进度；设置中清除指定书籍进度不会清除其他小说的记录。
